# dsh-channel-hub · 渠道中心

DSH 插件，保留三个入口：**渠道管理、数据看板、运行日志**。

当前版本：`0.1.0-alpha.1`。已完成构建、核心回归与真实宿主契约测试；尚未完成各渠道真实账号的端到端验收，不能当作稳定发行版。

## 已实现

- 基于 OFM 的账号认证与渠道内账号池，10 个渠道/产品条目独立注册。
- 每个渠道的「使用账号」支持自动选择或指定账号，设置重启后保留。指定后仅发布该账号动态发现且启用的模型，不因限流或失败静默切到其他账号；账号停用、删除或不支持模型时需重新选择。切换对后续请求生效，不改变已开始请求的账号选择；后台额度、续期和签到仍逐账号运行。
- **侧边栏独立面板**：点侧边栏的「渠道中心」图标即铺满整窗打开（和宿主的插件管理、任务管理同级），渠道 / 数据看板 / 运行日志三页不再挤在设置里。设置里的旧入口已移除 —— 那里固定 800px、可用宽度只有约 564px，放不下三页内容。
- **概览头压扁、正文铺开**：标题、说明、状态胶囊与四个小指标收进一行（约 87–91px），页面本身不滚动，只有内容区滚动，页签始终可见。
- **表格不出现横向滚动条**：长文本列（渠道 / 模型、账号）在格内折行并保底宽度，短列保持单行；窗口偏窄时自动隐藏「缓存读 / 缓存写 / 思考」这几列，而不是让你左右拖动。窄到仍需横向滚动时（例如同时开着侧栏），运行日志的表格在自己的容器里滚动，**横向滚动条始终停在容器底边**，不用先滚到最后一页。
- **运行日志聚焦关键列**：12 列，没有占位最宽的「详情」列、也没有逐行重复的「输入 / 输出」列；失败原因挂在「结果」徽标上，悬停即见。
- **数据看板上下排布**：「账号透视」与「模型性能」各占一整行（不再并排挤成半宽），表格宽度收到适合扫读的上限；两表的名称列以「来源 / 名称」显示，同一模型名在不同渠道上分别统计、不合并。
- **每日 Token 消耗按来源分段**：堆叠柱每一段对应一个渠道，颜色与图例一一对应；图例以「合计 N Token · M 天」开头，给出各渠道在**整个筛选区间**的合计（柱形是每天的量，两者口径不同、都标明）。占比很小的渠道也保留至少 2px 可见高度，不会因为量少就在图上消失。
- 按账号动态发现模型，保留最后成功快照；支持零倍率、思考档位、单模型开关与一键全部启用/全部禁用；模型行与 DSH 模型菜单显示上游目录给出的计费系数（Qoder `0×`、CodeBuddy `x0.29`、促销 `原价→折后价`），字段缺失不补值。
- 限时/限时段折扣如实展示：CodeBuddy 的 `夜间免费`、Qoder 的 `错峰 4 折` 作为琥珀色标签排在计费标签左侧，完整时段（`23:00–07:50`）一并显示；倍率本身只做字段归一化，不按时间窗口推算，因此一天里保持稳定。
- 上游业务错误按语义归类并给出可操作提示：Qoder「今日对话次数已达上限」（`110`）明确说明 UTC+8 当日 24:00 重置、可换账号或换模型；低优先级排队（`10605`）与额度用尽分开，确定性错误不做无意义重试。
- Gemini 工具调用回传推理签名：Gemini 3/4 强制要求当前轮每次工具调用都带上游下发的 `thoughtSignature`，缺了就整轮 400。签名落盘缓存后按「工具名 + 规范化参数」回填（命中不了按工具名取最近一次），thought part 上的签名也归属给对应的工具调用；真签名确实取不到时，对当前轮首个调用发上游文档给出的跳过校验值，避免整轮报废。
- 账号卡片直接显示额度读数（沿用 dsh-workbuddy-trae-qoder-connect 的思路）：各渠道额度响应在宿主侧归一成 `{ 剩余/总额, 进度条, 逐包明细, 失败原因 }`，浏览器只排版不做业务判断。查不到不显示成 0；token 与积分不合并，混单位时逐单位给读数（如 `94.54M / 100.00MToken`）；面值未知不补 100%；失效包单独提示「另有 N 已失效」；刷新失败保留上次成功读数并标注失败原因。逐包明细与原始响应可展开核对。
- 模型列表为单列，字号按高分屏上调一档（正文 15px、模型行 12px），活动标签与倍率标签不再互相挤占。
- 到期前三天续期、每小时巡检、同账号单任务合并和失败退避。
- 若续期后的凭据有效期仍不足三天，等待其新有效期的一半后再尝试（最长一天、最短三十秒），避免每次巡检都重复续期；手动续期可立即执行。
- 额度由宿主后台轮询：启动时检查，每五分钟更新，新增账号在下一次三十秒巡检时加入；手动与自动查询合并，失败保留上次成功读数并退避重试。停用账号仍维护凭据与额度，关闭管理页面不影响轮询。
- 后台自动签到：启动及每五分钟检查，今日已完成结果持久去重；账号卡片显示签到中、今日已签到、本次奖励、等待活动刷新、需手动处理或失败原因。失败退避重试，签到获得奖励后更新额度；Qoder 刷新前结果不计作今日完成。
- 删号不留残骸：删除账号会一并清掉它在账本里的四类快照（模型目录、额度、签到状态、账号名），不留孤儿行；渠道未注册（构建里已没有这个驱动）的账号在启动时以一条 warn 报告，可用 `accounts.orphans` 列出、`accounts.delete` 清理。这类账号既不会出现在渠道列表也不会出现在模型菜单里，所以只报告、不自动删除 —— 渠道装回来它们仍可用。
- 今日/全部 Token、轮次与步数、流式速度、整块吞吐、首字、缓存命中率、成功率、每日趋势、账号透视及模型性能。
- **按轮次记录**：一条用户消息引发的多次模型调用归为一轮，日志一行一轮、可展开看每一步；同时保留步数与每次上游尝试的明细，含账号、结果、耗时、速度、Token 和失败原因。
- 工作线程中的 SQLite；90 天明细、永久日汇总；按 profile 隔离。记账是旁路：单次调用有超时、未完成调用有上限，工作线程在就绪前退出也会立即失败 —— 数据库故障只记一条 `failedWrites`，不影响模型输出。统计的过滤条件下推到 SQL，历史增长不会拖慢面板刷新。
- 显式导入旧账号及可识别模型偏好，不修改旧文件、不导入旧统计。
- 管理界面沿用宿主主题变量：概览头、状态标签、响应式渠道卡片、账号子卡、KPI 与可滚动明细表；窄屏自动单列。

## 渠道

CodeArts、CodeBuddy / WorkBuddy 国区、WorkBuddy 国际版、Qoder CN/国际版、Trae CN IDE、Loomy、Raccoon、Gemini。

CodeBuddy CN 与 WorkBuddy 国区是同一产品（同一登录端点与账号体系），只保留 `buddy` 一个渠道，不设 `workbuddy-cn` 别名或迁移层。

Trae CN IDE 复用 OFM 已验证的本机回调登录：浏览器完成授权后，本地回调接收 `refreshToken`，经 `ExchangeToken` 换取访问凭据并写入账号池；登录 URL 使用 Trae CN IDE 的客户端与版本身份。旧 SOLO 已并入 CN IDE，只保留一个 `trae` 渠道，不单独注册 SOLO 或 `trae-cn` 副本。

旧 Qoder 会话若没有 `machine_id`，导入时跳过并提示重新登录，不补造设备身份。

Gemini 增加动态发现，但只发布 OFM 现有推理驱动支持且被远端确认的模型，不将远端所有模型冒充为已接通。其新增发现路径仍需真实账号验证。

## 开发与验证

```powershell
npm install --ignore-scripts
node scripts/extract-host.mjs
npm run check
```

宿主验证依赖来自本机 DSH `app.asar`，只提取到本项目 `node_modules`。可以用 `DSH_ASAR` 指定安装位置。缺少宿主时验证脚本退出 2；核心测试不需要宿主。

已验证的本机宿主为 DSH 库 `0.2.1-rc.2`，桌面运行时 Node `24.17.0` 支持 `node:sqlite`。其他版本尚未验收。

### 开发热重载

源码检出（存在 `src/index.ts`）时，插件会在 `dist/index.js` / `dist/ledger-worker.js` 更新后重建自身 Cordis fiber，便于在本机 DSH 窗口里实机调试，无需每次重启：

```powershell
npm run dev
```

`npm run dev` 监听 `src/` 与 `vendor/` 并运行构建；也可以直接运行 `npm run build`。自动热重载会等待在途推理完成，并在卸载前再次检查导入期间是否有新请求，然后释放旧 fiber（数据库 worker、观察器、续期定时器）并注册新代码，不会为了构建更新主动取消推理；真正退出插件仍会取消请求。导入失败时恢复旧模块缓存和旧注册。只有服务端入口 `dist/index.js` 与 `dist/ledger-worker.js` 会触发重载，浏览器入口 `dist/client.js` 的界面改动仍需刷新页面。`node_modules` 中的链接/junction 安装会先解析到真实目录再监视。安装包不包含 `src/`，因此不会在生产安装中启用；可用 `CHANNEL_HUB_HOT_RELOAD=0` 显式关闭。首次启用该能力仍需重启一次 DSH，之后的构建才会原位生效。

## 安装准备

`dist/` 已构建并随源码交付；`artifacts/` 提供本地安装包。新项目没有自动加入正在运行的 DSH，也没有替换旧插件。

可在 DSH 支持的本地插件安装流程中选择本项目；CLI 示例：

```powershell
dsh plugin --profile desktop add "D:\project\dsh-channel-hub"
```

安装后重启 DSH，在设置中打开「渠道中心」。先用新账号或少量账号验收，再迁移日常使用。

导入包含刷新令牌的登录态后，应停用旧插件中的对应账号，避免两个插件同时轮换同一份令牌。导入本身不会修改旧文件或自动停用旧账号。

## 数据与统计口径

数据位于 `$DSH_HOME/profiles/<profile>/channel-hub/`，默认 DSH_HOME 为 `~/.dsh`。凭据通过宿主凭据服务保存，引用名按 profile 隔离。

- 一次模型生成是一条请求；重试和换号是该请求下的尝试。
- 成功率按最终请求统计，取消与进程中断单列。
- Token 包含失败尝试已报告的消耗；缺失 usage 不等于零。
- 思考已包含在输出 Token，不重复累计。
- 缓存命中率只使用报告缓存数据的样本，并展示覆盖率。
- **速度分两个口径，不合并**：流式速度 = 输出 Token /（首字 → 结束），只有观测到首字才有样本；整块吞吐 = 输出 Token /（请求开始 → 结束），含首字等待、总是可得。拿总时长当流式速度会低估，拿首字窗口当整块吞吐会高估，因此两者分别展示、分别平均，并标出各自的样本数。
- 落库时若最后一条上游尝试尚未定稿（适配器先结束迭代、`ended` 由 fetcher 稍后补写），用请求自身的结束时刻与结果兜底，否则速度样本会被系统性丢成 0。
- 首字包含有效思考和工具参数增量；按北京时间分日，日汇总归入请求开始当天，跨日请求采用同一口径。
- 默认不保存提示词和回复正文。清理明细不会清掉历史累计。
- 账号级快照与控制状态同库不同键：快照按 `catalog:<provider>:<id>` / `balance:<id>` / `checkin:<id>` / `identity:<provider>/<id>` 存（键名集中在 `src/core/account-cleanup.ts`，新增一类必须同步登记），删号时随账号一起删；`import:<source>:<id>` 是导入源去重标记、不属于账号快照，删号时刻意保留，避免下次启动又把这个旧账号导回来。
